Laagan Adventure

Tour guide & travel company website for Zamboanga City, Philippines. Built on Next.js 15 + Sanity CMS.

🔗 Live: laagan-adventure.vercel.app 📦 Repo: JMS255/laagan-adventure 🛠 Framework: Next.js 15 App Router 📅 Last updated: June 3 2026 · Content sprint complete — 7 tours, hybrid content model, 28 static pages

Introduction

Project Overview

Laagan Adventure is a local tour operator website for Zamboanga City, Philippines. It lets travelers browse tour packages, view detailed itineraries, and inquire/book tours via a form or Messenger.

The site was designed to feel like a premium travel brand — think AutoCamp meets Trafalgar, adapted for a small local Filipino tour business. No online payment processing; booking is confirmed via Messenger.

Business

What it does

Showcases 5 tour packages, accepts booking inquiries, and drives users to Messenger for confirmation.

Audience

Who it's for

Local and visiting travelers in Zamboanga City looking to book guided tours to Santa Cruz Island and other destinations.

CMS

Content management

All tours, testimonials, gallery photos, and blog posts are managed through Sanity Studio at /studio.

Forms

Inquiry system

Contact form submits to Formspree. No backend required. Booking is confirmed via Messenger after inquiry.

Feature

Booking System

The booking system has three parts that share state via React Context (lib/booking-context.tsx):

Widget

BookingWidget.tsx

White card floating at the bottom of the hero. Fields: tour selector, date picker, guest counter. "Check Availability" opens the drawer.

Drawer

BookingDrawer.tsx

Slide-in panel from the right. Shows all 5 tour cards. Clicking a tour takes user to the contact page with pre-filled params.

Dropdown

TourDropdown (in Widget)

Custom-styled dropdown using createPortal to escape overflow:hidden on the hero section. Light theme, pink selection.

Calendar

DatePicker.tsx

Custom calendar component. No native browser UI. Smart above/below positioning. Pink selected date. Also uses createPortal.

Why createPortal? The hero section has overflow: hidden. Without portals, the dropdown and calendar get clipped. Both are rendered at document.body level with position: fixed coordinates from getBoundingClientRect().

Shared state flow

BookingProvider (app/layout.tsx)
  ├── Nav → "Book Now" button → openDrawer()
  ├── BookingWidget → sets tour/date/guests → openDrawer()
  └── BookingDrawer → reads state → links to /contact?tour=...&date=...&guests=...

Tour Detail Page

Inspired by Trafalgar's tour pages. Located at /tours/[slug]. Fully server-rendered with client islands for interactive parts.

Page sections (top to bottom)

Hero
Full-width 480px image with dark overlay. Shows destination badge, tour title, duration, price.
Sticky Tabs (TourTabs.tsx)
Sticks below the nav. "Your Tour" / "What's Included" / "Reviews". Active tab updates as you scroll via IntersectionObserver scrollspy.
Itinerary (2-column grid)
Pink location pin icons + time badge + activity text. Matches Trafalgar's sightseeing highlights layout.

2-column grid of inclusions with green ✓ checkmarks. Pulls from Sanity inclusions field.

Renders if mapQuery is filled in Sanity. Uses Google Maps iframe (no API key needed). Shows the tour area.
FAQ Accordion (FAQAccordion.tsx)
6 default Zamboanga-specific FAQs built in. Override per tour by filling the faq field in Sanity.
Sticky Booking Card (sidebar — desktop only)
Price, duration, "Book This Tour" → /book/[slug], "Ask a Question" → Messenger. Trust badges. Sticks as you scroll. Hidden on mobile (≤600px) via .tour-detail-sidebar class — replaced by StickyBookBar.
StickyBookBar.tsx (mobile only)
Fixed bottom bar on tour pages, visible on ≤768px only. Appears after 400px scroll (scroll listener with passive:true). Shows price + "Book This Tour →" link + "💬 Ask" Messenger link. z-index 149 (below Messenger float at 200). Handles notched phones via env(safe-area-inset-bottom).
What's Included section
Full-width pink-tinted section. 2 columns: inclusions (green ✓) and exclusions (red ✕).
Reviews
Up to 3 testimonials from Sanity. Shows empty state if none exist yet.
Similar Tours
3 other tour cards auto-pulled from Sanity, excluding the current tour. Uses SIMILAR_TOURS_QUERY.

Feature

Destination Pages

Trafalgar-style destination browsing. A horizontal card strip on the homepage lets users explore by destination (Santa Cruz Island, Zamboanga City, Basilan, ZAMBASULTA). Clicking a card opens a rich destination detail page at /destinations/[slug].

How tours appear on destination pages

The destination detail page fetches Sanity tours where destination == $destinationTag. The destinationTag values are:

Destination pageSanity tour.destination must equal
Santa Cruz Island"Santa Cruz Island"
Zamboanga City"Zamboanga City"
Basilan Province"Basilan"
ZAMBASULTA"ZAMBASULTA"
To add tours to a destination page: open Sanity Studio → edit the tour → set the Destination Tag field to exactly the string above. The page revalidates within 60 seconds.

Reviews

CTA
Navy section linking to /contact?tour=[destination name] + Messenger link.

Migration to Sanity (future)

When you're ready to manage destination content from Sanity Studio:

  1. Create a destination document type in sanity/schemas/destination.ts with the same fields as the Destination interface in lib/destinations.ts
  2. Add DESTINATIONS_QUERY and DESTINATION_QUERY to lib/sanity.ts
  3. In app/destinations/[slug]/page.tsx: replace DESTINATIONS.map() in generateStaticParams with a Sanity fetch, and replace getDestination(slug) with a Sanity query
  4. Everything else (page sections, CSS, tour fetching) stays identical

Feature

Contact Page

Split-screen layout at /contact. Left panel: dark navy with tour highlights and contact info. Right panel: white inquiry form.

The form submits to Formspree (https://formspree.io/f/xpwzgwnn). Fields auto-populate from URL params: ?tour=...&date=...&guests=... — set when coming from the booking widget or drawer.

Booking flow: Widget → "Check Availability" → Drawer → "Book this tour" → Contact page with pre-filled tour/date/guests → Formspree submission → Owner replies via Messenger.

Mobile UX Overhaul — Trafalgar Pattern ✅ Complete

Between Sprint 5 and Sprint 6, a full mobile audit was completed. The site was built desktop-first; several sections had no mobile breakpoints and the tour detail page had a critical conversion gap — the booking CTA was buried at the very bottom of the page on mobile. Based on a Trafalgar.com mobile UX analysis, 7 issues were identified and fixed.

Trafalgar insight applied: The sticky bottom bar is the single biggest conversion booster on mobile travel sites. Their "thumb zone" CTA is always visible, price-anchored, and zero friction. Now ours is too.

Critical fixes

StickyBookBar.tsx — mobile booking CTA
New client component. Fixed to bottom of viewport on tour detail pages (mobile ≤768px only). Appears after 400px scroll. Shows price + "Book This Tour →" + "💬 Ask" buttons. Desktop sidebar hidden via .tour-detail-sidebar class to avoid duplicate CTAs. Messenger float lifted to bottom:100px on mobile to clear the bar.
Photo wall — missing mobile breakpoint
Inline repeat(3,1fr) grid had no responsive override. At 375px the 3 columns rendered at ~115px each. Replaced with .photo-wall class → collapses to repeat(2,1fr) at 600px. First/last wide photos (span 2) still work correctly.
Group tours section — missing mobile breakpoint
Inline 1fr 1fr grid with padding: 56px 48px per cell — at 375px rendered two ~170px cells with huge padding. Replaced with .group-tours-grid / .group-tours-cell classes → stacks to 1-col at 600px, padding reduces to 40px 20px.

Medium fixes

Nav hamburger tap target — 24px → 48px
.nav__toggle had padding: 4px, giving a ~24px tap area. Mobile minimum is 48px. Fixed: padding: 12px 8px in the 600px breakpoint.
Spotlight content padding on mobile
.spotlight__content kept padding: 40px 32px even at 600px (from the 900px breakpoint). Added padding: 24px 20px override at 600px for breathing room.
Messenger float clearance
Messenger float sits at bottom: 28px. Adding a sticky bar at bottom:0 (~72px tall) would obscure it. Added bottom: 100px at 600px breakpoint.

Sprint 7 — SEO, Performance & Growth Features 🔄 Next

Based on the June 3 research session. Prioritized by ROI — quick wins first, then medium-term features. Full detail in RESEARCH.md.

Quick Wins — Do First

GA4 funnel events — CRITICAL
Without tracking, there's no data to optimize with. Events to add: tour_view (on detail page load), booking_started, booking_step_1_complete, booking_submitted, deposit_initiated, deposit_completed, messenger_click (with source param), traveler_filter_selected, promo_code_applied. Then configure a Funnel Exploration in GA4 to see where users drop off.
JSON-LD structured data — TouristTrip + LocalBusiness + FAQPage
TouristTrip schema on every tour detail page. LocalBusiness in layout.tsx (site-wide). FAQPage on tour pages (Google shows FAQ entries as expandable rich snippets in search results — free SERP real estate). BlogPosting on blog posts. None of this is currently implemented.
Canonical URLs in generateMetadata
Booking flow creates URLs with params (?date=&guests=). Without canonicals, Google indexes these as duplicate pages of the tour detail. Add alternates: { canonical: url } to all generateMetadata calls.
useCdn: true on Sanity read client (30 minutes)
lib/sanity.ts currently has useCdn: false, meaning every page request bypasses Sanity's Fastly CDN and hits the origin directly. Switching to useCdn: true cuts 200–400ms off page load globally. The write client for /api/book already uses a separate writeClient, so this change only affects reads.
Guest booking confirmation email (Resend)
Currently guests receive nothing after booking — no email, no reference number sent to them. They must wait for Messenger/phone contact from James/Ivy. Adding a transactional email (Resend — 3,000/month free) with booking ref, tour, date, and contact info eliminates "did my booking go through?" messages.
Title tag + meta description rewrite for all tours
Current format: "Laagan Adventure — Tour Services in Zamboanga City" (generic). Target format: "[Tour Name] — ₱X/person | Laagan Adventure Zamboanga". Searchers want to see price and location in the title. This directly increases click-through rate from Google search results.

Medium-Term Features

Slot capacity / "X spots left" system
Santa Cruz Island has a real 400-visitor/day cap. Add a maxCapacity field to the tour Sanity schema and a bookedCount derived from bookings per (tourSlug + date). Show "X spots left" and grey out fully-booked dates in BookingOverview. This is the single highest-impact conversion feature not yet built — authentic urgency drives bookings.
Destination guide pages — wire up /destinations/[slug]
The route exists and generates static params, but the pages are not linked from nav, sitemap, or tour cards. Each destination (Santa Cruz Island, Yakan Weaving Village, Fort Pilar, etc.) as a permanent content-rich pillar page targets long-tail SEO queries like "Santa Cruz Island Zamboanga complete guide". These rank indefinitely as evergreen reference content.
On-demand ISR via Sanity webhook
Currently all ISR is time-based (revalidate=60). When James or Ivy publishes a tour update in Sanity Studio, it takes up to 60 seconds to appear live. A Sanity webhook hitting /api/revalidate can trigger revalidatePath('/tours') and revalidatePath('/tours/[slug]') immediately on publish — updates appear in seconds.
Replace photo wall img tags with next/image
The homepage photo wall and tour UGC photo wall use raw <img> tags. next/image provides automatic WebP/AVIF conversion, lazy loading, and correct responsive sizes. With Sanity images, use urlFor() + next/image with the sizes prop. This is a direct LCP improvement.
